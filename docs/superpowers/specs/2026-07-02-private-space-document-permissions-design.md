# 私人空间文档权限设计

## 目标

私人空间（组织标签以 `PRIVATE_` 开头）中的文档只能由文档所有者和管理员查看。新上传到私人空间的文档必须为私有，客户端不能选择公开。历史数据迁移不在本次范围内。

## 后端规则

- 上传接口以服务端规则为准：当目标组织标签以 `PRIVATE_` 开头时，无论客户端传入什么值，持久化的 `isPublic` 都为 `false`。
- 普通用户访问文档列表或执行知识检索时，私人空间文档仅在文档所有者是当前用户时可见。用户拥有相同私人组织标签不能获得访问权。
- 管理员可在文档列表和知识检索中查看所有私人空间文档。
- 基于单个资源的预览、下载、切片等访问继续由资源授权过滤器保护；私人空间规则优先于公开标记，避免错误数据绕过权限。
- 非私人组织的现有公开、组织内私有和所有者访问语义保持不变。

## 前端规则

- 上传到私人空间时，弹窗固定提交 `isPublic=false`，并明确提示私人空间文档固定为私有。
- 上传到普通组织时，保留“公开/私有”选择，默认选择私有。
- 文档列表保留公开状态展示和筛选，以兼容现有非私人空间历史文档。

## 测试

- 上传私人空间时，即使请求传入公开，后端仍保存为私有。
- 普通用户不能在列表和搜索中看到其他用户的私人空间文档。
- 文档所有者可以看到自己的私人空间文档。
- 管理员可以看到所有私人空间文档。
- 单资源访问不能因错误的 `isPublic=true` 绕过私人空间限制。
- 前端类型检查与构建通过，上传弹窗不存在公开选择。

## 非目标

- 不修正数据库或 Elasticsearch 中已有文档的公开标记。
- 不引入 Flyway、Liquibase 或其他数据库迁移框架。
- 不改变普通组织现有文档的访问模型。
